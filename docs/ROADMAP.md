# Пътна карта

Принципи: телефонът е основният инструмент на терен; работи без връзка; нулев разход; NetBox 4.1.11 е крайната точка; един код за Cloudflare и за контейнер.

## Етап 1 — теренен опис (0.7) ✅

Огледи, етажи и помещения, шкафове по U, устройства със снимки, офлайн PWA, JSON архив. Worker сервира приложението и `/api/me` (потребител от Cloudflare Access).

## Етап 2 — екипна синхронизация (0.8) ✅

- D1 за записите и отделна D1 база за снимките, и двете с юрисдикция ЕС (безплатно, без карта; ~500 MB на база). Преминаване към R2 при нужда.
- Всеки запис има версия; телефонът пази опашка от промени; сървърът ги номерира; всеки изтегля само новото.
- При конфликт — сравнение поле по поле и избор.
- Авторът на всяка промяна е от Cloudflare Access. Предстои: проверка на подписа на Access JWT (Cf-Access-Jwt-Assertion) като втора защита.
- Адаптери за SQLite файл и папка/S3, за да върви същото API в контейнер (Node).

## Етап 3 — каталог от NetBox

- `cloudflared` тунел до вътрешния NetBox, защитен с Access service token.
- NetBox API token **само за четене**, пазен като Worker secret.
- Нощно копие (Cron Trigger) в D1: tenants, sites, locations, manufacturers, device types (височина, портове), roles.
- На терен изборът е от реалния каталог, вместо свободен текст.

## Етап 4 — преглед и експорт

- Екран „Готовност за NetBox“ по реда на импорта: Tenant → Site → Locations → Racks → Devices → Interfaces → Ports → Cables.
- CSV пакет, сверен с NetBox 4.1.11 `bulk_import.py`.
- След импорта — изтегляне на NetBox ID и свързване на записите, за да е следващият оглед сравнение.
- По-късно и запис през API (с токен за запис и потвърждение).

## Етап 5 — етажи и планове

- Импорт на план от PDF/DWG (декодерите се свалят само при нужда).
- Очертаване на помещения върху плана; шкафове на плана; 3D изглед.

## Извън плана засега

Кабели и ODF трасета, етикети за Brother P-touch с QR — от версия 0.6, ще се пренесат след етап 4.
